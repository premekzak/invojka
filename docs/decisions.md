# Decision log

Newest first. Each entry records what was decided and why, and who decided when it was the owner's call.

**When a later decision overrides an earlier one, the earlier entry starts with _Superseded_ and says by what.** Read those only for history; the current state is always in [ui.md](ui.md), [architecture.md](architecture.md) and the other pages. Several changes to the same thing on one day are merged into one entry that describes where it ended up.

## 2026-10-17

- **Navigation: a one-row peach header instead of the sidebar** (the owner's requests, refined in several steps the same day). The logo and "Invojka" on the left, the pages as centred pills, and the business on the right with a save tick before it. The tick's tooltip says "Vše uloženo v 18:05" and "Složka: faktury"; errors still show as a crimson chip with words. "Nová faktura" left the navigation: it sits at the right end of the Faktury title row (Home and customers have their own). The owner was told pills break the design system's "no pills" rule and chose them for navigation only, at a 12 px radius. The peach moved from the sidebar to the band, the `sidebar-*` colour roles became `header-*`, and the orange current-page edge was dropped, so the logo is the only orange. The owner also wanted the folder's full path shown; the browser never reveals it, so only the name is. How it got here: the sidebar's current page first became a full-width tab joined to the page, then the sidebar became a two-row centred header, then one row, then the logo moved left and the business right. → [ui.md](ui.md)
- **More businesses, one folder each** (the owner's request: "what if I have other businesses"). Chosen over one folder with a subfolder per business, which would have meant moving the owner's existing files inside OneDrive. Each folder stays self-contained (it can go to that business's accountant), and nothing is shared, including customers (the owner's choice). The cost: after a browser restart each business may need its own permission click. The owner found the bare folder window confusing, so adding a business is a dialog: name the business, read what the window will ask, and Invojka creates the folder itself. → [architecture.md](architecture.md#businesses)
- **Modern headings, rust warnings and one gradient ("G2")** (the owner's choice from a design-canvas round of four title fonts, each with one gradient in a different place). Headings are Bricolage Grotesque 700 with tight tracking instead of the Newsreader serif; table headers are small grey labels without a filled bar. Overdue and missing rates are rust `#9e4501` (the owner found red aggressive); errors and delete stay crimson, because they are rare. The owner was told rust is close to the identity orange, so it is kept much darker and always labelled, and the "Co dál" icons became ink. Primary buttons get a subtle top-to-bottom blue gradient, the only gradient in the app. → [ui.md](ui.md)
- **Theme "Warm paper" (F4)** (the owner's choice from a design canvas of about twenty variants, narrowed in three rounds: orange sidebars, then warm paper with espresso, then more blue). A peach `#fdb081` sidebar with espresso text, a faintly cream page `#fffaf6` with white cards, warm greys, espresso `#342117` instead of black, blue from the owner's `#099bc1` for actions (darkened to `#077491`) and charts, and the owner's darker orange `#fa8d4e` used sparingly: the logo letter and the current-page edge. Crimson `#b7162d` replaced red so it stays apart from orange; green stays. Dark mode: warm near-black, an espresso sidebar, lighter blue `#47b3d7`. The owner was told which colour rules this breaks (a large tinted sidebar, a cream page, a second hue) and chose it anyway; they are recorded in `ui.md`. This replaces the grayscale theme and the trial below. → [ui.md](ui.md) Since then (same day): the sidebar became the header band and the current-page edge was dropped, so the orange is only in the logo; warnings became rust (see "G2").

- _Superseded by Warm paper (the same day): the page is faintly cream._ **A white page, for now** (the owner's request). The light `paper` value went from `#f6f7f8` to white, the same as the cards, which stay apart thanks to their `line` border. Dark mode is unchanged. → [ui.md](ui.md)
- **"Co dál" icons without a tile** (the owner's request: icons should have a transparent background). The grey square behind the icon (pale red for the warning card) is gone; the icon is ink, or red for the warning card, and lines up with the card title. → [ui.md](ui.md) Later the same day the icons became the title colour, and the warning card's icon rust ("G2").
- **Status labels right-aligned in the invoice list** (the owner's request). This replaces the rule that status labels stay left-aligned. → [ui.md](ui.md)
- **The product is renamed Invojka** (the owner's choice). - **Target: a free public app with a website and marketing, and no cloud on purpose** (the owner's decision). Competing with paid cloud services (Fakturoid, iDoklad) on privacy, price, no account and data ownership. → [product.md](product.md)
- **Setup convenience is a main focus** (the owner's priority). The single file stays, so the app and the website must guide a beginner from the download to the first invoice: where to keep the file, how to open it, which browser, which data folder. → [product.md](product.md#first-run-from-download-to-first-invoice)

## 2026-10-11

- _Superseded by Warm paper (2026-10-17)._ **Grayscale, except red and green** (the owner's request). The blue accent is gone: `accent` is now ink, so primary buttons, the selected filter, the active page and focus are black (light) or near-white (dark). Chart bars are mid grey (this year) and light grey (last year). Red (errors, overdue) and green (saved, Paid) keep their colour. Accent and identity now share a value; they stay separate roles, and what you can click is marked by shape (filled button, underline, sidebar edge, focus edge), which the design system already required.
- **Subtler table lines and row hover** (the owner's request). Row dividers and the line under the table header use a new `rule` role, lighter than `line`, and `row-hover` moved closer to the card colour. Both are decorative, so no contrast minimum applies; text on the hovered row keeps 4.5:1.
- **Invoice list: right-aligned dates, a lighter row hover, and a green "Paid" label** (the owner's requests). Dates are now right-aligned with tabular digits, like the amounts. Hovered rows use a new `row-hover` role (`#f4f5f6`, dark `#1c1e1f`), because the old hover used the table-header grey, which the owner found too dark. Paid is now `success` text with a check icon. The owner was told it went against two rules (green only for confirmations, and Paid kept grey for grayscale), and chose green text plus a check over a green chip. The check keeps it apart from Overdue without colour. This supersedes the 2026-10-01 "Paid is plain grey" rule. → [ui.md](ui.md) (The hover colours here are from the old palette; the current ones are in ui.md.)
- **No accent on status labels, and the paid buttons became verbs** (the owner approved both). "Vystaveno" used to be outlined in the accent colour although it isn't clickable. Now Issued has a solid grey outline and Draft a dashed one. The "Zaplaceno" / "Nezaplaceno" buttons were renamed "Označit jako zaplacené" / "Označit jako nezaplacené", because they read like the status. On list rows the button is icon-only (a check, with the verb as tooltip and `aria-label`), so the table keeps its width. → [ui.md](ui.md)

- **Field borders made clearly visible** (the owner: "input borders are not visible"). The first ledger line used the card-border `line` grey (1.5:1) on the sides, which disappeared. Now a new `input-side` role (about 2:1; light `#aeb1b5`, dark `#505356`) draws the top and sides, and the bottom `input` edge is darker, at 4:1 or more (light `#7a7d81`, dark `#76797d`). The ledger-line look stays, and the design system is updated. → [ui.md](ui.md)

From a tester's feedback (relayed by the owner):
- **Issued invoices can take updated customer details on purpose** (the owner chose this over deleting issued or cancelled invoices). The tester had a wrong customer detail and couldn't fix it on an issued or cancelled invoice, because issued invoices keep their snapshot. Now, when the customer was edited after issue, the invoice shows "Údaje odběratele se od vystavení změnily" with a "Použít nové údaje" button. The number stays, so the sequence keeps no gaps. Saving an issued, paid or cancelled invoice now also rewrites its PDF in the folder, so the file matches. Deleting stays drafts-only. → [data-model.md](data-model.md)
- **`{MM}` in the numbering pattern** (the tester's request). With a month in the pattern, the sequence restarts every month, e.g. `{YY}{MM}{NN}` → `261001`. → [invoicing-rules.md](invoicing-rules.md)
- **The registration field explains itself.** The English label is now "Business register entry" (it was "Registration", which the tester didn't understand). Under it, a one-sentence hint with the sole-trader example sentence says it's printed on the invoice.

- **The design system is colour-agnostic** (the owner's request: the scheme may change later). It names only colour roles (`accent`, `danger`, `surface`…), never hues or hex. Its tokens hold role values directly, with no palette layer, and it lists the contrast checks any new scheme must pass. The current Ledger values pass all of them. Scheme-specific exceptions (the picker-pure accent) stay in [ui.md](ui.md). The app already has this split: palette in `src/index.css`, roles everywhere else.
- **A design system, "Invoicer Ledger", with a forms standard** (the owner's request; references: GitHub, Cloudflare and Rechain). It records the current tokens and adds rules for fields: the label above in 14 px `fg`, the hint under the field, a 2 px blue focus edge, an error message with an icon, required fields marked with `*`, and the save button kept enabled so errors show when it's pressed. It is published as a private Design System artifact and isn't in the app yet. → [ui.md](ui.md) (It went into the app the same day, see "The forms standard is in the app". The artifact keeps the old name.)
- _Superseded the same day by "Field borders made clearly visible" (new `input-side` role and darker values)._ **Field border: the "ledger line"** (the owner's choice from five options). The top and sides are `line` (`#d4d6d8`; dark `#343538`). The bottom edge is the existing `input` role with a new, lighter value (`#86898d`; dark `#6b6e72`), which reaches 3.3:1 or more on card and paper. Black text inside a dark grey box looked heavy. A plain hairline (the GitHub look, 1.5:1) was rejected because it fails the 3:1 rule for controls; the bottom edge keeps fields easy to find. → [ui.md](ui.md)
- **The forms standard is in the app** (the owner's go-ahead). Every field now uses one `.control` box. Labels are 14 px `fg` with a hint or error under the field, required fields get `*`, and units sit inside the field. Save buttons stay enabled and show errors instead of being disabled, and app settings are rows. One shared `Select` replaced four copied class strings. Selects and text areas now get a focus edge. → [ui.md](ui.md)
- **Working rule: design changes go into the design system too** (the owner's request). When the owner asks for a design change, update the design system as well. If the request breaks one of its principles, say so first. → `CLAUDE.md`

## 2026-09-30

- **The Home screen's number tiles became a sentence, and the greeting became a joke by time of day** (the owner's request). The sentence is easier to read than four boxes and can say what matters ("all of it is overdue"). Greetings don't use a name, because Czech needs the vocative case. → [ui.md](ui.md)
- **Demo mode anonymizes the owner's own data in memory rather than showing generic sample data.** The owner wants screenshots and videos without creating data or touching files. Anonymizing the real data keeps the screens realistic: the same number of invoices, the same statuses and dates. At first, amounts were scaled by one hidden factor. The owner then asked for the amounts and charts to be made up too, so amounts are now invented per month and don't reveal real revenue or trends. → [architecture.md](architecture.md#demo-mode)
- _Superseded by Ledger (2026-10-01) and later Warm paper (2026-10-17)._ **Colour scheme: beige papers + plain CSS blue, red only for overdue** (the owner's choice after six rounds of mockups). Cream content, kraft sidebar, blue headlines, buttons, links and charts; last year's bars are a pale blue tint. This replaces the petrol/teal/ochre scheme. The owner wanted fewer colours and text that stands out. → [ui.md](ui.md)
- **Bigger, bolder headlines** (the owner's request). Page titles are 36 px and section titles 24 px, all in Newsreader 600. Using one serif weight made the file about 50 kB smaller. (Sizes still hold; the face became Bricolage Grotesque 700 on 2026-10-17, "G2".)
- **Typography review** (the owner's request, against Google Fonts, Material 3, Ramotion and Mosaiq). Fixes: embed Inter 500, because `font-medium` was rendering as regular; raise faint grey and warning text to 4.5:1; chart text at least 11 px; page titles in Newsreader 400 without negative tracking; tabular Inter instead of monospace for numbers; drop Inter `cv11`. The file grew by about 130 kB. → [ui.md](ui.md) (The Newsreader parts were superseded by Bricolage Grotesque on 2026-10-17.)
- _Partly superseded: headings are Bricolage Grotesque (2026-10-17), charts are blue, and navigation pills are the one exception to small corners. Not the same as the 2026-10-17 theme also called Warm paper._ **Warm paper look: cream background, serif headlines (Newsreader), Inter for everything else, small corners (max 6px), no all-caps labels, no shadows; teal and ochre charts.** The owner's choice. The serif is embedded as small woff2 subsets and used only in the UI, not in the PDF. The radius scale is capped in `@theme` so every `rounded-*` class stays subtle. → [ui.md](ui.md)
- **Exchange rates come from ECB (automatic), ČNB files (uploaded) and manual entry.** The owner allowed external requests as long as no user data is sent, and asked for manual entry. ČNB can't be fetched because of CORS; a proxy was rejected because it routes requests through a third party. → [exchange-rates.md](exchange-rates.md)
- **Revenue charts on the Home screen, by month (this year vs last) and by year.** The owner asked for them. They're hand-built SVG with no chart library, to keep the single file small and styling fully under control.
- **Foreign-currency revenue without a rate is excluded, and the UI says so.** A silent zero would under-report the NZD years.
- **Issuing an invoice saves its PDF into the data folder** (`pdf/<year>/<number>.pdf`), so every issued invoice has its document on disk.
- **PDFs use `@react-pdf/renderer` with embedded Inter TTFs.** They render the same everywhere and can be saved straight into the folder; the browser's print dialog can't do that.
- **QR Platba only for unpaid CZK invoices.** Czech banking apps expect CZK, and paying a paid invoice makes no sense.
- **A customer can be created from the invoice's customer search**, and "Edit customer" saves the invoice as a draft first. This came from the owner's feedback that the app should guide them and not lose work. (On 2026-10-17 the owner found this silent draft surprising; a dialog instead is proposed in the roadmap.)
- **Drafts follow customer edits; issued invoices keep their snapshot.** An issued invoice must match what was sent.
- **Home screen with "Co dál" (Next steps) cards.** The owner found the first post-setup screen confusing ("it does nothing").
- **Onboarding Finish waits for the save; 0-byte files count as missing.** Fixes a real incident in the owner's OneDrive folder.
- **The source template is renamed to `index.html`; the only `invoicer.html` is the build output.** The owner opened the template and saw a blank page. (Since the rename it is `invojka.html`.)
- **Single bundled HTML file** (the owner's choice). Tested: it works from `file://`, including folder access.
- **JSON, one file per type** (the owner's choice over one file per invoice). Sync conflicts are handled by a `lastModified` check and a conflict banner.
- **JSON rather than YAML.** YAML silently changes values: `01234567` becomes a number and loses its leading zero, and `no` becomes a boolean.
- **One business profile per data folder.** A different business uses a different folder, which keeps the model and numbering simple. Still the rule: since 2026-10-17 the app can remember several such folders and switch between them.
- **Chrome and Edge first, storage behind an adapter.** The File System Access API is Chromium-only; Firefox and Safari can get a browser-storage adapter with zip export later.
- **Stack:** React, TypeScript, Vite, Tailwind, Zustand, Zod, i18next, date-fns, papaparse. Common, typed, and small enough for one file.
- **Money in minor units, dates as ISO strings, IDs as strings, totals always computed.** See [data-model.md](data-model.md).
