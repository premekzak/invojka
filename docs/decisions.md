# Decision log

Newest first. Each entry records what was decided and why, and who decided when it was the owner's call.

**When a later decision overrides an earlier one, the earlier entry starts with _Superseded_ and says by what.** Read those only for history; the current state is always in [ui.md](ui.md), [architecture.md](architecture.md) and the other pages. Several changes to the same thing on one day are merged into one entry that describes where it ended up.

- **The tax estimate knows main and secondary activity** (the owner: it must). - **Accountant export: CSV and ISDOC, not Pohoda XML** (from the Fakturoid list). ISDOC is the Czech standard and Pohoda, Money S3, ABRA and others import it, so one format covers most accountants; Pohoda's own XML waits until someone needs it. ISDOC was written against the official 6.0.2 XSD and every kind of document validates. Files come as one ZIP from a small built-in writer (no CDN, no library), or go into `export/<period>/` in the data folder. Each exported document records `exportedAt`.
- **Tax and insurance estimate from money received, projected to the whole year** (from the Fakturoid list). Income is counted by payment date, as tax records count it, not by issue date like revenue, so the two figures on Home can differ on purpose. The estimate is for the whole year at this year's pace, because the yearly minimums make a "so far" figure meaningless early in the year. Rates live per year in `src/domain/taxes.ts`; a year without rates says so rather than guessing. Shown for sole traders only (a setting, on by default), since a company doesn't pay these. 2026 uses the retroactive June 2026 amendment (35 % minimum social base, flat-tax band 1 at 9 162 Kč).
- **E-mails open in the user's own mail program** (`mailto:`), with the PDF attached by hand. No server to send from, and a Gmail compose link would hand the customer's address and amount to Google in a URL. Templates are stored only when the user changes them, so better built-in texts still reach everyone. The payment sentence is one placeholder, `{platba}`, so cash invoices or a missing account don't leave a broken sentence. The editor header got a "Více" menu for the rarer actions, because send, PDF, mark paid and save no longer fitted on one row.
- **Bank payments by reading a downloaded statement** (from the Fakturoid list). No bank connection: it would need a server and the bank's token, and bank data would pass through a third party. The user downloads GPC, CAMT.053 or CSV, and the browser reads it; the file is never sent or stored. GPC first because almost every Czech bank exports it and its layout is fixed; CSV columns are found by name, so new banks often work without code changes. Only exact matches are ticked; a different amount waits for the user. Also: a VAT payer without a DIČ now sees it among the missing details on Home (§ 29 requires it on tax documents).
- **VAT payers' advances: tax document first, then the final invoice** (part 3, approved). The tax document has its own series `ZD…`, so neither the invoice series nor the proformas get gaps. Its lines are worked out from the money received (net from gross, so base + VAT add up to it), and the final invoice deducts the money received plus the tax document's base and VAT per rate, so the balance comes out at exactly 0 Kč when the advance covered everything, even when VAT rounding leaves the tax document a haléř off. Neither the proforma nor the tax document counts as revenue; the final invoice does, in full.
- **Proformas: the final invoice carries the full amount and deducts the advance** (part 2, approved). The final invoice is the revenue, in full, by its issue date; the proforma never counts, so nothing is counted twice. When the advance covers it all, issuing marks it paid with the advance's date, so the user doesn't mark a 0 Kč invoice paid by hand. Payers don't get the final invoice until part 3, because without the advance's tax document it would show the VAT wrong. Also fixed: issuing a new invoice straight away lost its PDF preview, because the editor remounts when the URL changes from /new to the id.
- **Issued documents are locked; corrections go through credit notes** (the owner: locked by default, each one can be unlocked when needed; no global switch).
